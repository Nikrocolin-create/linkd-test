Ключевой момент: в Java умножение long молча переполняется по модулю 2⁶⁴. То есть на самом деле считается:

scramble(id) = (id · M) mod 2⁶⁴,   где M = 6364136223846793005

Почему это перестановка (а не хаос с коллизиями): M — нечётное, значит взаимно просто с 2⁶⁴. У такого M существует обратный элемент по модулю 2⁶⁴, а раз есть обратный — умножение
это биекция: каждый id даёт уникальный результат, и теоретически его можно вернуть назад (это и был тот самый unscramble, который ты удалил).

Почему соседние id дают «далёкие» коды: умножение на большую константу «размазывает» изменение младшего бита по всему 64-битному числу. id=1000 и id=1001 отличаются на 1, а их
произведения — на целое M ≈ 6.3·10¹⁸. Верхние биты, из которых потом лепится код, оказываются совершенно разными. Это классический приём — тот же множитель используется в
LCG-генераторе Кнута (MMIX).

LinkService.create — главные риски:
- A. Конфликт alias всё ещё даёт 500. Твоя проверка findByShortCodeAndExpiresAtAfter (только не-истёкшие), а unique constraint — глобальный. Истёкший alias проходит проверку, но
  падает на constraint → 500. Плюс гонка check-then-act. Нужно ловить DataIntegrityViolationException на save и мапить в 409 — это прямое требование дня.
- B. Дедуп по longUrl возвращает новый expiresAt, а не found.getExpiresAt() — тихий баг консистентности.
- C. IllegalArgumentException → 409 слишком широко: любой такой exception завтра станет 409. Заведи доменное AliasConflictException.

CreateLinkReq — намешаны @AllArgsConstructor + @Builder + ручной конструктор (запутанно); у alias нет @Pattern (можно прислать пробел/слэш/кириллицу в URL); у ttl нет @Positive.

ExceptionHandler — хорош (RFC 7807), но нет обработчика DataIntegrityViolationException (тот самый ключ к 409).

Тесты — два серьёзных замечания:
- MeterRegistry — синглтон на класс, счётчики накопительные → equalsCustomAliases ассертит 49, но стартует не с нуля. Флейки по построению.
- equalsCustomAliases по названию должен проверять конфликт alias → 409, а по факту гоняет тот же cache hit/miss с пустым alias. Ключевого кейса дня в тестах нет.

Чтобы закрыть день до ~100%

1. Настоящий 409 через перехват DataIntegrityViolationException (закрывает и гонку, и истёкший alias).
2. Тест: занять существующий alias → 409.
3. Починить флейки-тест метрик (считать delta).
4. Исправить expiresAt в дедупе по URL.
5. Проработать письменно depth-вопросы (JVM heap Eden→Survivor→Old; enumeration/permutation).
